## 理解 / 笔记

### enum 枚举

枚举适合表示一组数量有限、提前确定的选项。

```java
public enum TaskStatus {
    TODO,
    DONE
}
```

相比普通字符串，枚举可以限制合法取值，减少拼写错误。

### Repository 与 Mapper

```text
MyBatis
→ 数据访问层通常叫 Mapper
→ 经常需要自己编写 SQL

Spring Data JPA
→ 数据访问层通常叫 Repository
→ 基础增删改查由框架提供
```

Repository 仍然属于 DAO 数据访问层，只是在 JPA 项目中通常使用 `repository` 作为包名。

### JpaRepository 为什么能直接使用

```java
public interface UserRepository
        extends JpaRepository<User, Long> {
}
```

Spring 启动后会为 Repository 接口创建实现对象，基础 CRUD 由 Spring Data JPA 提供，Hibernate 再根据实体映射生成 SQL。

常用方法包括：

```java
findAll();
findById(id);
save(entity);
deleteById(id);
count();
```

### 后端开发顺序

以后不再先批量写 Repository 方法，而是从具体业务出发：

```text
1. 选择一个具体功能
2. 用中文写出 Service 业务流程
3. 标出需要访问数据库的步骤
4. 推导 Repository 需要的方法
5. 在 Service 中串起业务和数据库操作
6. 最后由 Controller 接收请求
```

也就是：

```text
业务流程
→ 数据需求
→ Repository 方法
→ Service 实现
→ Controller
```

### 用户注册业务流程

```text
1. 接收 username、email、password、confirmPassword
2. 检查两次密码是否一致
3. 检查用户名是否重复
4. 检查邮箱是否重复
5. 将 password 编码为 passwordHash
6. 创建 User 对象
7. 保存 User
8. 返回 id、username、email
```

需要访问数据库的步骤：

```text
检查用户名
→ existsByUsername(String username)

检查邮箱
→ existsByEmail(String email)

保存用户
→ save(user)
```

其中 `save()` 已由 `JpaRepository` 提供，不需要重复声明。

### DTO、Service 与依赖注入

注册请求对象：

```text
RegisterRequest
→ username
→ email
→ password
→ confirmPassword
```

注册响应对象：

```text
RegisterResponse
→ id
→ username
→ email
```

不能直接返回完整的 `User` 实体，避免暴露 `passwordHash` 等内部字段。

`AuthService` 需要：

```text
UserRepository
→ 查询和保存用户

PasswordEncoder
→ 将明文密码编码为 passwordHash
```

IoC 是把对象的创建和管理交给 Spring；DI 是 Spring 把需要的依赖注入到业务类中。当前准备使用构造器注入。
