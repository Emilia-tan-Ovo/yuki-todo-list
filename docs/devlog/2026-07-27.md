## 理解 / 笔记

### Auth

`Auth` 一般表示 `Authentication`，也就是身份认证。

```text
AuthController
→ 注册
→ 登录
→ 退出登录
→ 查询当前用户
→ Session 登录状态
```

### 全局异常处理器

可以把 `GlobalExceptionHandler` 简单理解为 Web 接口层共用的 `try/catch`。

```text
Controller 调用 Service
→ Service 抛出业务异常
→ GlobalExceptionHandler 捕获异常
→ 转换为 HTTP 状态码
→ 组装 ErrorResponse
→ 返回前端
```

常用注解：

```text
@RestControllerAdvice
→ 声明全局异常处理类

@ExceptionHandler
→ 指定某个方法负责处理哪一种异常
```

### 为什么前后端都要校验

```text
前端校验
→ 提升使用体验
→ 尽早提示输入错误

后端校验
→ 保证服务器收到的数据合法
→ 防止绕过前端直接发送错误请求
```

基础格式校验放在 DTO：

```text
@NotBlank
@Email
@Size
```

业务规则放在 Service：

```text
两次密码是否一致
用户名是否重复
邮箱是否重复
```

### 用户注册的数据流

```text
Apifox 发送注册请求
→ AuthController 接收 JSON
→ @Valid 校验请求字段
→ AuthService 执行注册业务
→ UserRepository 查询并保存
→ MySQL 生成用户数据
→ Controller 建立 Session
→ 返回 201 Created
→ Apifox 保存 Cookie
```

### 后端开发流程

1. 选择一个具体功能
2. 阅读 API 文档
3. 用中文写出业务流程
4. 确定请求和响应数据
5. 标出需要访问数据库的步骤
6. 推导 Repository 方法
7. 在 Service 中实现业务
8. 分析可能出现的业务错误
9. 补 DTO 校验和异常处理
10. 用 Controller 接收请求
11. Maven 编译
12. 使用 Apifox 测试
13. 检查数据库并更新日志

可以简记为：

> 想业务 → 找数据 → 写 Service → 补边界 → 接 Controller → 做测试
