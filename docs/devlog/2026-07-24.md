## 理解 / 笔记

### 接口文档怎么写？

一项接口通常需要写清楚：

1. 接口用途；
2. 请求方法和路径；
3. 请求参数或请求体；
4. 成功状态码与响应示例；
5. 主要失败状态码。

> 简单接口写清请求和响应；复杂或容易误解的地方，再补一两句说明。

### 设计 API 时要考虑的问题

1. 请求地址是什么？
2. 使用 `GET`、`POST`、`PUT`、`PATCH` 还是 `DELETE`？
3. 前端需要提交什么数据？
4. 后端成功后返回什么？
5. 出错时返回什么？

### 常用请求方法

| 方法 | 用途 |
|---|---|
| `GET` | 查询数据 |
| `POST` | 创建数据 |
| `PUT` | 提交完整的新版本 |
| `PATCH` | 只修改部分字段 |
| `DELETE` | 删除数据 |

### HTTP 状态码

| 范围 | 含义 |
|---|---|
| `1xx` | 信息提示，请求还在处理 |
| `2xx` | 请求成功 |
| `3xx` | 需要进一步操作，常见情况是重定向 |
| `4xx` | 客户端提交的请求有问题 |
| `5xx` | 服务器处理请求时出现问题 |

本项目常用状态码：

```text
200 OK             查询或修改成功
201 Created        创建成功
204 No Content     删除或退出成功，无响应体
400 Bad Request    请求数据或格式错误
401 Unauthorized   未登录或登录失效
404 Not Found      数据不存在或无权访问
409 Conflict       数据发生冲突，例如名称重复
```

### 错误响应

```json
{
  "code": "COURSE_NAME_DUPLICATE",
  "message": "课程名称已存在"
}
```

- `code`：供前端程序判断错误类型；
- `message`：供页面展示给用户。

### JSON 数据结构

- 查询单个对象时，返回一个 JSON 对象；
- 查询列表时，返回数组；
- 一门课程可以包含一个近期任务数组；
- 没有查询结果时返回空数组 `[]`，不返回 `null`；
- 标准 JSON 中不能写 `//` 注释。

### PUT 与 PATCH

```text
PUT   → 提交资源的完整可修改数据
PATCH → 只提交发生变化的字段
```

例如：

```text
PUT /api/tasks/{taskId}
→ 修改任务标题、课程、截止日期和状态

PATCH /api/tasks/{taskId}/status
→ 只快速修改任务状态
```

### 用户数据隔离

前端不提交 `userId`。

后端通过当前登录状态确定用户身份，并检查课程和任务是否属于当前用户，防止通过修改编号访问其他用户的数据。

### MVP

`MVP` 是 `Minimum Viable Product`，即“最小可行产品”。

当前项目先完成最核心且完整的流程：

```text
注册 / 登录
→ 创建课程
→ 创建任务
→ 查询、修改和删除课程与任务
→ 切换 TODO / DONE
→ 用户数据隔离
→ 退出登录
```

忘记密码、邮箱验证码、头像和提醒等功能暂不属于首版范围。
