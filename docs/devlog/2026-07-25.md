## 理解 / 笔记

### Maven 依赖异常

命令行执行 Maven 编译成功，说明代码和 `pom.xml` 没坏，问题出在 IDEA 的 Maven 关联。

解决方法：取消链接 `backend` Maven 项目，再重新导入 `backend/pom.xml`。

### 环境变量保存数据库密码

配置文件中写：

```properties
spring.datasource.password=${DB_PASSWORD}
```

然后在 IDEA 运行配置中设置 `DB_PASSWORD` 环境变量，避免把真实密码提交到 GitHub。

### JavaBean 和 JPA 实体类

普通 JavaBean：

```text
私有属性 + 无参构造 + Getter + Setter
```

JPA 实体类：

```text
普通 JavaBean + 数据库映射注解
```

### 常用 JPA 注解

- `@Entity`：说明当前类是实体类。
- `@Table`：指定对应的数据库表。
- `@Id`：标记主键。
- `@GeneratedValue`：设置主键生成方式，对应 MySQL 的自增主键。
- `@Column`：设置属性对应的字段名和字段约束。
- `@ManyToOne`：表示多对一关系，例如多门课程属于一个用户。
- `@JoinColumn`：指定关联关系使用的外键列，例如 `user_id`。

可以简单记成：

```text
@ManyToOne：说明是什么关系
@JoinColumn：说明外键存在哪一列
```

### 为什么用 `User`，而不是 `userId`

数据库中保存的是：

```text
courses.user_id
```

Java 实体中写的是：

```java
private User user;
```

这样可以用对象关系表达“这门课程属于哪个用户”。JPA 会负责把 `Course.user` 和数据库里的 `user_id` 对应起来。

这并不一定能减少数据库查询，主要是为了让代码更符合**面向对象**的写法。
