## 理解 / 笔记

### Spring Boot MockMvc

MockMvc 会经过 Spring MVC 的请求映射、JSON 转换、参数校验和异常处理，但不需要真正启动 8080 服务器。

本项目使用：

```java
@SpringBootTest
@AutoConfigureMockMvc
@ActiveProfiles("test")
@Transactional
```

测试请求会经过：

```text
MockMvc
→ Controller
→ Service
→ Repository
→ yuki_todo_test
```

`@Transactional` 会在每个测试结束后自动回滚测试数据，避免测试之间互相影响。

### 自动化测试与冒烟测试的分工

- MockMvc：主要验证接口逻辑、参数校验、异常状态码、用户数据隔离等场景。
- Apifox：主要验证 Session、Cookie 和完整真实业务流程。

当很多测试同时出现 `Errors`，但没有业务断言失败时，应先检查环境变量、数据库连接和 Spring 配置，而不是认为所有接口同时出错。
